# 0003. MITM 域名变化的处理

- 状态：生效（2026-10-23）
- 日期：2026-10-23

## 背景

读取 HTTPS 请求，需要使用者在自己的代理客户端里为对应域名开启 MITM，并信任自己生成的证书。MITM 域名只能写在订阅（模块 / 插件）里，没法在脚本运行时下发；而读取规则可以运行时下发（见 0002）。所以只有增删来源、改匹配域名时，订阅才需要更新。

各客户端会不会自动刷新 URL 订阅、在什么条件下刷新，阶段 0 之前还不确定。

## 决策

订阅内容由平台实时生成，MITM 列表只包含已配置来源的域名，不对全部域名做 MITM。域名集合变化时，平台发出 `subscription.mitm_changed` 事件，通知里附上各客户端的“安装 / 更新模块”链接，由使用者本人在手机上点开确认更新。

## 后果

- 好处：MITM 范围始终和已配置的来源一致；更新订阅这一步在手机上可见，并由本人确认。
- 代价：每次增删来源，使用者都要在手机上点一次更新。
- 后续：阶段 0 验证 Surge 的安装链接能否覆盖更新同一 URL 的模块，以及各客户端自动刷新的条件。

## 可推翻条件

阶段 0 证实客户端能可靠地自动刷新订阅时，改为以自动刷新为主、通知只作提醒。
