# 0002. 手机端按规则取值，服务端复核

- 状态：生效（2026-10-23）
- 日期：2026-10-23

## 背景

使用者本人的 App 发出的请求里带着登录态（请求头、Cookie、body 里的字段）。要把这些值同步到平台，有两种做法：手机端脚本按规则取出需要的字段再回传；或者手机把原始的请求头和 body 整个回传，由服务端取值。

整包回传会把与来源无关的数据（其他请求头、完整 body）也带到平台，回传体积也更大；手机端取值则要求各客户端的脚本 API 能拿到需要的位置。

## 决策

手机端只有一份通用脚本 `ferry.js`。它在运行时从平台拉取声明式规则（带 ETag 和本地缓存），只取规则里声明过的字段，在本地按哈希去重后再回传。服务端收到后，按同一套规则再复核一遍：请求来自哪个来源、字段是否声明过、取值位置是否匹配；不符合的一律丢弃。

## 后果

- 好处：平台只会收到声明过的字段，回传最小化；新增来源不用改脚本，也不用重装订阅（MITM 域名变化除外，见 0003）。
- 代价：取值引擎要写两份，JS 版在手机上跑，Go 版在服务端复核，两份要用同一组测试样例对齐。
- 后续：脚本单测在 Node 里模拟各客户端的 API；脚本出任何错都要放行原请求。

## 可推翻条件

阶段 0 发现各客户端脚本 API 的差异大到没法用一层适配抹平时，改成“手机回传原始数据、服务端取值”，并写一篇新的 ADR。
