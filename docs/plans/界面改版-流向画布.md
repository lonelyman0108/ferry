## 背景与目标

《界面与易用性优化》阶段 1–5 之后，信息都在界面上，但还是按对象类型拆成 8 个页面（总览、来源、订阅、登录态、推送、通知、系统设置、账户）。处理一件事仍要跨页：

1. **待处理只有计数**：总览说“1 个推送失败”，点进推送页再筛选、再重试；待审核要先到登录态页、再打开身份、再找到那个值。
2. **一条数据的去向看不出来**：手机 → 来源 → 身份 → 推送规则 → 目的地 这条链，分散在四个页面上。某个目的地失败时，看不出影响了哪些来源。
3. **登录态页和来源页是同一件事的两半**：身份就挂在来源下面，却在两个页面上。

2026-11-12 用 huashu-design 出了三个方向的可点 demo（一字状态、流向画布、密表），选了**流向画布**，并要求：查看具体内容时图自动聚焦、让出空间。设计稿存在 `docs/design/界面改版-流向画布.html`，截图 `docs/design/界面改版-总览.png`、`docs/design/界面改版-聚焦.png`。

**目标**：

- 打开总览就看到整张流向图，哪里断了一眼可见；待处理的事在收件箱里当场处理完。
- 点任何一个节点，图收成窄栏只留相关链路，详情占主体；一页看完这个对象的全部。
- 深浅两色都完整支持。

**不做**：

- 不改“使用范围”里的约束：手机端回传通知默认开启，事件和通知不带值，查看原值要留审计。
- 不改数据模型；除新增只读接口外，不改已有接口的行为（总览接口只加字段）。
- 不做画布拖拽、缩放、自由布局。三列（设备 → 来源 → 目的地）固定排布，节点多了纵向滚动。
- 《界面与易用性优化》阶段 6 的新增功能不在本计划内，改版完成后在新界面上做。

## 设计

### 1. 主题 token

颜色全部从 `web/src/style.css` 的 CSS 变量走，`:root` 是浅色，`.dark` 是深色。新增画布专用变量。

| 变量 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--background` | oklch(0.985 0.003 285) | oklch(0.17 0.012 285)（约 #0E0D14） | 页面与画布底 |
| `--card` | oklch(1 0 0) | oklch(0.205 0.012 285) | 节点卡、面板 |
| `--border` | oklch(0.91 0.006 285) | oklch(0.29 0.014 285) | 发丝线 |
| `--primary` | oklch(0.50 0.16 285) | oklch(0.68 0.14 285) | 选中、主按钮（紫色压低饱和，取自 demo） |
| `--canvas-dot` | oklch(0.85 0.006 285) | oklch(0.30 0.012 285) | 点网格 |
| `--edge` / `--edge-failed` / `--edge-idle` | 中性灰 / 红 / 浅灰 | 同理 | 连线：正常实线、失败红虚线、未连通灰虚线 |

状态色（success / warning / destructive / info）沿用现有变量，深浅各调一次，保证在 `--card` 上 ≥4.5:1。状态始终配文字，不只靠颜色。

### 2. 外壳

- **桌面**：左侧栏（品牌、6 项导航、底部搜索与命令 ⌘K、主题切换、账户）；顶部条（面包屑、状态胶囊「2 件事要处理 · 另有 2 条提醒」、跳转或执行）。
- **手机**：顶部品牌和搜索；底部 6 项导航，带待处理角标。
- **状态胶囊的口径**：“要处理”= 待审核 + 推送失败（需要动手）；“提醒”= 即将过期、已过期、订阅待更新、从未连通、等待重试。点胶囊回总览并展开收件箱。
- **⌘K**：跳转到来源、订阅、目的地；执行“重试全部失败的推送”“新建来源”“切换深浅色”。

### 3. 总览：流向画布

- 三列：设备（订阅）→ 来源 → 目的地。停用的来源、目的地虚线框放在列尾。
- 连线：订阅覆盖来源（全部来源的订阅连到每个启用的来源）；推送规则把来源连到目的地。线型取这条推送规则最近一次推送的状态：成功实线、失败红虚线（线上标原因）、没推过或订阅未连通灰虚线。
- 节点卡内容：
  - 设备：名称、客户端、状态（未安装 / 已安装 / 已连通，另有规则过时）、最近连接；
  - 来源：名称、key、身份数、最早过期、最近回传，有待审核或推送失败时右上角徽章；
  - 目的地：名称、类型、变量数、最近推送结果。
- 收件箱：画布左上角浮层，可折叠；分“要处理”“提醒”两组，每条带就地操作。
  - 待审核：通过 / 驳回（`/versions/{id}/approve|reject`）；
  - 推送失败：立即重试（`/pushes/{id}/retry`）、查看目的地；
  - 即将过期：知道了（只在本机收起，存 localStorage）；
  - 订阅待更新：重新安装（打开安装引导）。
- 画布按可用区域自适应：收件箱展开时整体右移，空间不够时等比缩小，再不够就纵向滚动。
- 底部图例和最近 7 天统计（回传、推送、失败、通知）。

### 4. 聚焦与详情

- 进入聚焦：点任意节点，或打开 `/sources/:id`、`/subscriptions/:id`、`/destinations/:id`。
- 窄栏只留相关节点，纵向排列：
  - 来源：上面是覆盖它的设备，下面是它推到的目的地；
  - 设备：它覆盖的来源；
  - 目的地：推到它的来源。
- 其余节点收成「另外 N 个节点已收起」胶囊，点了回全图；Esc、面包屑「总览」、「返回全图」也回全图。在窄栏里点别的节点，聚焦跟着切换。
- 过渡：共有的卡片做 FLIP 位移约 360ms，其余淡出，详情从右滑入；`prefers-reduced-motion` 时直接切换。
- 详情顶部是标题、状态徽章、3–4 格概要，以及**和它有关的待处理**（带同样的就地操作）。
- 来源详情（两栏）：
  - 左栏：身份与当前值（脱敏；查看原值走 `/versions/{id}/reveal` 并留审计）、版本历史与审核（原登录态页的身份详情整体搬入）、推送规则与最近结果（新建、编辑、手动推送）；
  - 右栏：覆盖它的订阅、读取规则（原来源编辑器，折叠，展开后是编辑表单）、接入清单、最近记录。
- 设备详情：安装状态、安装引导、传输方式与密钥操作、覆盖的来源、最近连接记录。
- 目的地详情：配置（编辑、检测）、推到它的推送规则、推送记录与重试。

### 5. 其余页面

- **来源**（`/sources`）：来源列表（卡片行），点了进聚焦；新建来源走原编辑器弹窗。
- **订阅**（`/subscriptions`）：设备列表，点了进聚焦。
- **推送**（`/destinations`）：两个标签页，目的地、通知（通知渠道 + 通知规则 + 通知记录）；推送规则在来源详情里配，这里只读汇总。
- **记录**（`/activity`）：时间线，一次同步一条：回传（哪台设备、哪个来源）→ 校验或检测 → 审核 → 推送（各目的地结果）→ 通知。可按来源、结果筛选。
- **设置**（`/settings`）：访问地址、账户（密码、API 令牌）、外观（深浅色）、审计日志。

### 6. 后端接口

都是只读、登录后可用、API 令牌也可读。

| 接口 | 返回 | 说明 |
|---|---|---|
| `GET /api/v1/overview` 加 `items` | `[{kind, severity, source_id, identity_id, version_id, push_id, subscription_id, destination_id, title, detail, at}]` | kind：`pending_review`、`push_failed`、`push_retrying`、`expiring`、`expired`、`outdated`、`never_connected`；severity：`action`（要处理）/ `notice`（提醒）。口径与现有计数一致，加测试保证条目数等于计数 |
| `GET /api/v1/flow` | `{devices, sources, destinations, edges}` | 节点带画卡片所需的字段；edges 分 `covers`（订阅 → 来源）和 `pushes`（推送规则：来源 → 目的地，带最近状态、错误、时间） |
| `GET /api/v1/sources/{id}/lane` | `{source, identities, bindings, subscriptions, recent}` | identities 带当前值（脱敏）、过期、待审核数；bindings 带每个身份最近一次推送；recent 是最近 20 次同步 |
| `GET /api/v1/activity?source=&result=&before=` | `{items, next}` | 以批次为主线，关联版本、推送任务、通知审计；分页 50 条 |

实现要点：

- 复用 `latestPushes`、`pushState`、`identityPushStates`、`mask`、`subscriptionDocsFrom`，不另写口径。
- 时间比较和取最大值放在 Go 里（SQLite 聚合时间是字符串，见已知的坑）。
- 不改表结构；新 SQL 在 PG、MySQL 临时容器里各跑一次 `go test ./internal/server/ ./internal/store/`。

## 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 节点多了画布太长 | 一屏看不全 | 三列各自纵向排，停用的放列尾；超过一屏时画布滚动、收件箱固定 |
| 连线位置靠测量 | 窗口变化、字体加载后错位 | ResizeObserver + `document.fonts.ready` 后重算；连线层只读位置不参与布局 |
| 来源编辑器 1200 多行，搬进详情容易出问题 | 编辑规则出错 | 阶段 4 先原样嵌入，只换外层；不在本计划里重写编辑器 |
| 一次改动面太大 | PR 难审 | 每个阶段 1–3 个 PR；阶段 1 之后旧页面一直能用 |
| 深色模式下状态色对比度不够 | 看不清 | token 定好后用脚本算对比度，写进验证记录 |
