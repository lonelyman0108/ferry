## 背景与目标

给自己的青龙加签到脚本时，脚本需要本人账号的登录态（token 等），过期后要手动从手机里复制出来，而且每个 App 都要单独写一个读取插件。Ferry 是一个**独立的自用平台**（不依赖青龙）：
在平台上配置每个来源需要哪些字段 → 生成一个通用订阅，装到自己手机的代理客户端（Surge / Loon / QX / Stash / Egern）→ 本人打开 App 时读到最新的值，回传到平台 → 平台存版本、做校验 → 同步到自己配置的目的地，并按规则发通知。

**不做**：签到脚本本身、对全部域名做 MITM、在手机上保存目的地的密钥、任何面向他人账号或设备的用法。

### 使用范围

Ferry 是**自用**的个人自动化工具：把**本人账号**在**本人设备**上的登录态（App 自己发出的 token、Cookie 等）同步给**本人**的自动化任务（如青龙里的签到脚本），省去每次登录态过期后手动复制。

- 只同步使用者自己的账号；来源由使用者本人在后台逐个配置。
- 只在使用者自己的设备上运行：订阅需要使用者在自己的代理客户端里手动安装，并信任自己生成的证书。
- 不做静默采集：每次回传都会在手机上弹出可见通知（默认开启），后台保留完整的审计记录。
- 不面向第三方设备或他人账号，也不提供任何隐藏、绕过或扩散的能力。

## 详细设计

### 1. 来源配置

- **匹配规则**：域名（精确匹配或 `*.` 通配，汇总起来就是 MITM 列表）、路径正则、请求方法、`需要 body`（只有字段要从 body 取时才开，开了才会让客户端开启 `requires-body`）。
- **取值位置**：`header`、`cookie`（可指定 key）、`query`、`body_json`（点路径，如 `data.user.id`）、`body_form`、`regex`（在 URL 或 body 上跑正则，取第一个捕获组）。
- **值类型**：`text`、`jwt`（解析出 `exp`、`sub`）、`cookie`（解析成键值对）、`json`、`number`、`bool`。另有 `sensitive` 标记：开了就加密存储、界面打码。
- **账号键**：指定一个字段作为账号标识。缺了账号键的回传，归到“默认账号”。
- **合并窗口**：同一账号的字段可能分散在多个请求里，在窗口时间内（默认 5 分钟）到达的字段合成一批，作为一次更新。
- **输出变量**：变量名 + 模板（Go `text/template`，只开放少数安全函数）。每个目的地还能改用别的变量名。
- **手机端行为**：手机通知（默认“每次回传都通知”，可改为“首次 / 变化时”）、回传最短间隔、调试日志开关。

### 2. 回传协议

`POST /api/v1/sync`，请求头带订阅 token：

```json
{ "source": "ninebot", "matcher": 1, "device": "iphone-surge",
  "fields": { "authorization": "ey...", "device_id": "6..." },
  "seen_at": 1792000000 }
```

返回结果手机端会用到：`accepted` / `unchanged` / `rejected` / `pending`，再附一句给手机通知用的文字。
手机端先把值的哈希和本地缓存比一下，没变就不回传。回传超时 3 秒，不管成功与否、出没出错，最后都放行原请求。

### 3. 版本与状态

```
回传 ─→ 去重（和当前值相同 → 只更新 last_seen）
     └→ 新版本 [pending] ─→ 静态校验 ─→ 主动探测(可选) ─→ [valid] ─→ 自动推送 / 等审核
                                    └──────────────→ [rejected]（保存并通知）
推送记录：每个目的地一行 [queued → success / failed(重试 n 次)]
```

- 当前值 = 最新的 `valid` 版本。回滚 = 把某个旧版本设回当前值，并重新推送。
- 保留策略：每个字段保留 N 个版本或 N 天，取二者中更宽松的那个，默认 50 个 / 180 天。
- JWT 类型：快到期时（默认提前 24 小时）发“即将过期”事件。

### 4. 主动探测

```yaml
probe:
  request: { method: GET, url: "https://cn-cbu-gateway.ninebot.com/portal/api/user-sign/v2/status",
             headers: { Authorization: "{{.authorization}}" } }
  expect: "status == 200 && json.code == 0"     # expr-lang/expr 表达式
  identity: "json.data.userId"                  # 可选：用探测结果识别身份
  timeout: 5s
```

### 5. 订阅与通用脚本

- 订阅链接 `/{format}/{token}`，格式为 `surge`、`loon`、`qx`、`stash`、`egern`。内容实时生成，包括：MITM 域名（`%APPEND%`）、脚本声明（各匹配规则的 URL 正则、是否需要 body）、脚本地址、参数（平台地址、token）。
- 脚本：只有一份 `ferry.js`，由平台提供，包含一层环境适配（`$httpClient`/`$task`、`$persistentStore`/`$prefs`、`$notification`/`$notify`）。
- 访问地址：可以配多个（如局域网、公网域名）。每个订阅选一个主地址，可以再配一个备用地址。Ponte 之类的地址也只是一个域名，按普通访问地址配置（决策 15 已撤销）。

### 6. 目的地

- 接口：`Upsert(ctx, outputs []Output, identity Identity) error` 和 `Test(ctx) error`。
- 青龙：用 OpenAPI，应用只开“环境变量”权限。多身份有两种放法：一个身份一条（备注写 `ferry:<来源>:<身份>`，按备注找到对应那条再更新）；或者合成一条（用 `&` 连接）。写入后确保这条变量是启用状态。
- Webhook：可自定义 URL、请求方法、请求头、body 模板，并可配 HMAC 签名。
- 失败处理：指数退避重试 5 次，仍然失败就发“推送失败”事件；在界面上可以手动重推。

### 7. 通知

- 事件：`identity.new`、`value.updated`、`value.rejected`、`value.pending_review`、`push.failed`、`value.expiring`、`subscription.mitm_changed`。
- 规则：事件 + 来源过滤 → 渠道列表。通知内容有模板，敏感值一律打码。
- `subscription.mitm_changed` 的通知里附上各客户端的“安装 / 更新”链接。

### 8. 初始化与配置

- 首次启动没有配置文件时，进入 `/setup` 向导：选数据库（SQLite 路径 / PG / MySQL 连接，测连通后才能下一步）→ 建管理员 → 设访问地址 → 生成主密钥（显示一次，要求确认已备份）→ 写入 `ferry.yaml`。
- 环境变量可以覆盖配置文件（`FERRY_*`），方便用 Docker 部署。
- 认证：管理员用账号密码（bcrypt）登录，会话存在 HttpOnly Cookie 里。API token 只存哈希；订阅 token 存哈希（用来查找）加一份主密钥加密的原文（界面要能再次显示订阅链接，MITM 变化的通知也要附安装链接），两者都可以吊销或更换。

| 订阅 token 外泄 | 他人可写入错误的值 | 只能写已声明的字段；有校验和探测兜底；token 可吊销；限流 |
| 主密钥丢失 | 敏感值无法解密 | 初始化时强制确认已备份；文档写明恢复方式 |
| 各客户端脚本 API 不一致 | 部分客户端功能缺失 | 差异表已出（`docs/clients.md`），缺什么就在文档里注明降级 |
| Surge、Loon 同一请求只运行第一条匹配的脚本 | 和其他模块撞上同一 URL 时，Ferry 的脚本不运行 | 匹配正则尽量精确；文档提醒使用者 |
