## 背景与目标

开发计划的阶段 8 完成后，管理界面的视觉已经统一：弹窗外壳、徽章、配色都有规范。2026-10-27 做了一次界面评审：读完全部前端页面和对应接口；在本机起临时实例，灌入伪造数据，造出收集中、待审核、驳回、即将过期、推送重试等状态；在桌面、手机和深色模式下逐页截图。问题主要不在视觉，而在下面五处：

1. **该处理的事看不见**：待审核、推送失败或重试中、即将过期、收集中的批次，总览和列表上都不显示。总览的失败数是前端从最近 200 条审计、100 条推送里数出来的，漏掉了有效性检测不通过和人工驳回，重试中的推送也不算。
2. **流程断开**：新增一个来源，要在来源、订阅、手机、目的地之间来回切换，保存后没有任何提示。订阅显示的“已安装”实际是“脚本拉过规则”，订阅文件的下载没有记录，所以也提示不了“模块待更新”。
3. **推送结果看不见**：身份详情看不出当前值有没有推出去；一直推送失败的目的地，在列表上看不出异常。
4. **文案不统一**：同一个事件，事件标签、通知标题、状态各有一种说法；审计日志直接显示代码；“规则”“映射”“探测”这些词有歧义，或前后叫法不一。
5. **一致性与手机适配**：列表、空状态各有三种写法；没有加载状态；手机宽度下，表格里的操作被挤出屏幕；另有几个小 bug。

**目标**：打开总览就知道有没有要处理的事，点一下就到处理的地方；新增来源时照着一份清单走完；界面上的说法统一。

**不做**：

- 不改“使用范围”里的约束：手机端回传通知默认开启，事件和通知不带值，查看原值要留审计。
- 不改代码里的类型名、表名、接口路径和前端路由。

## 详细设计

### 1. 文案与改名

- 侧栏：总览 / 接入（来源、订阅）/ 数据（登录态）/ 分发（推送、通知）/ 系统（系统设置），每页的说明随之更新。
- 事件标签按「术语」里的表改。通知标题本来就是新说法，不动。
- 推送任务的触发原因：后端改为记固定代码 `value.updated`、`approve`、`activate`、`manual`，界面翻译成“新值生效 / 审核通过 / 恢复旧值 / 手动推送”。已有的记录里是中文原因，原样显示。
- 后端报错和原因同步改。比如“‘按身份拆分’的映射需指定身份”“目的地或映射已停用”“映射不存在”“探测出错”“探测未通过”“探测的 method 不支持”“向导令牌无效”，以及启动日志里的初始化令牌提示。
- README 的核心概念表和正文、`docs/clients.md` 一并改。

### 2. 总览与状态统计

新增 `GET /api/v1/overview`，只读，API 令牌可以调用。返回三部分：

- `attention`：需要处理的计数，包括：
  - 待审核的值；
  - 推送异常：最近 7 天最终失败的任务，加上当前在等待重试的；
  - 即将过期或已过期：当前值 3 天内到期，或已经过期；
  - 收集中的批次；
  - 从未连通的订阅；
  - 待更新的订阅（阶段 3 起）。
- `sources`：每个来源的身份数、最近回传时间、最近 7 天被驳回的数量、推送异常数、推送规则数、待审核数。
- `counts`：来源、订阅、身份、目的地、通知渠道的总数和启用数。

界面：

- 总览顶部是“需要处理”列表，每项点进去就是处理的页面，带好筛选条件；没有要处理的事时显示“一切正常”。五张流向卡片压成一行计数，去掉序号和箭头。“下一步”引导补上“订阅还没连通”“还没有通知规则”两种情况。
- 侧栏角标：登录态显示待审核数；推送显示推送异常数；订阅显示待更新数，阶段 3 接上。切换页面时刷新，另外每 60 秒刷新一次。
- 登录态列表：`GET /api/v1/identities` 给每个身份加上待审核数，以及当前值里最早的到期时间。列表加“状态”列（待审核 / 即将过期 / 已过期 / 正常），可以按状态筛选。

### 3. 订阅状态、安装与接入引导

- **存储**：`subscriptions` 加两列。`file_fetched_at` 记下载订阅文件的时间，按分钟更新；`file_mitm_hash` 记当时的 MITM 域名哈希。原有的 `mitm_hash` 继续用来判断要不要发变更通知。
- **状态**：
  - 未安装：没下载过订阅文件，脚本也没拉过规则。
  - 已安装：下载过订阅文件，脚本还没拉过规则。
  - 已连通：脚本拉过规则。
  - 待更新：下载时的 MITM 哈希和现在的不同。它和前三档同时显示。

  “最近拉取”和“最近加密通信”合并成“最近连接”。
- **兼容**：迁移前就有的订阅没有这两列的值。拉过规则的订阅按“已连通”算；`file_mitm_hash` 为空时不判断待更新，等下次下载订阅文件后才有。
- **订阅预览**：新增 `GET /api/v1/subscriptions/{id}/preview`，返回生成的订阅文件和 MITM 域名列表。它走管理接口，不更新 `file_fetched_at`，不会被算成“已安装”。
- **订阅卡片**：只显示状态、最近连接、来源范围和“安装 / 更新”按钮。订阅链接、脚本链接、预览、更换令牌、更换密钥都收进“更多”。去掉和品牌图标重复的客户端徽章；有了待更新状态，页面顶部的 MITM 说明也去掉。
- **安装弹窗**：按客户端分四步，每步用该客户端自己的叫法（模块、插件、重写、覆写）。
  1. 安装：给链接和二维码。
  2. 开启 MITM、信任证书。
  3. 填传输密钥：只有加密订阅有这一步，密钥在弹窗里显示和复制。
  4. 打开 App 验证：实时显示是否已连通。
- **接入清单**：新建来源保存后，或者改了匹配域名后，显示四步：
  1. 加入哪些订阅：直接勾选，保存就更新订阅。
  2. 哪些订阅待更新：给出安装入口。
  3. 推送到哪个目的地：直接建推送规则。
  4. 等待第一次回传：实时显示收集中的状态。

  来源卡片上也能随时打开这份清单。

### 4. 推送结果展示

- **接口**：
  - 按推送规则返回某个身份最近一次推送。“合并为一条”的推送规则，取该来源最近一次推送。
  - 推送记录可以按状态、目的地、来源筛选。
  - 新增 `POST /api/v1/pushes/{id}/retry`：等待重试的任务立即执行；最终失败的任务重新排一次。
- **身份详情**：加“推送”一节。逐条列出这个来源的推送规则，每条给出最近一次推送的状态、时间、错误，带“手动推送”按钮。
- **推送页**：目的地卡片显示最近一次推送结果，包括成功、失败或等待重试，以及时间。推送记录支持上述筛选和“立即重试”；变量名显示成标签；被跳过任务的原因用中性色显示。
- **登录态列表**：加“推送”列，显示最近一次推送是否成功。

### 5. 一致性、手机适配与问题修复

- **列表**：能配置的对象用卡片行（`ListRow`），记录和日志用表格。访问地址、推送规则、API 令牌改用卡片行；推送记录、审计日志、登录态列表还是表格，手机宽度下不能出现横向滚动。
- **空状态**统一用 `Empty`，带下一步按钮。**加载中**用 `Skeleton`。
- **筛选参数**统一为 `?source=<来源标识>`，现在推送规则用的是 id。筛选框统一放在页面标题右侧；有标签页的页面放在标签内容第一行的右侧，和说明文字同一行。
- **表单**：保存按钮不再因为必填项没填而置灰；点了之后就地标出缺什么。共用 `useFormCheck`（`lib/form.ts`），`FormField` 加 `error`；`FormDialog` 去掉 `disabled`，免得以后又用回去。缺前置条件（比如还没有目的地）时，打开表单就在对应项下面说明。
- **审计日志**：
  - 操作者和对象显示名称，由后端一起返回。
  - 动作翻译成中文。
  - 可以按类别筛选：登录、配置、回传、推送、通知、查看原值。
  - 颜色看结果，不看动作名的后缀。现在发送成功的 `notify.value.rejected` 显示成红色。
  - 类别、中文名、结果都由后端按动作算出，筛选在后端做（列表是分页的）；详情换成界面上的叫法（客户端、目的地类型、事件名等）在前端做，用 `types.ts` 里已有的对照表。
- **细节**：字段名称和标识相同时只显示一次。
- **修复**：
  - 版本列表传了不存在的字段名时，返回了全部字段，改为报错（`internal/server/identities.go`）。
  - 回传里有字段被驳回时，其余字段不再判断是否到齐，只能等合并窗口结束，改为照常判断（`internal/ingest/ingest.go`）。整条回传都被驳回时也会开一个批次，要等后台任务来关，期间算在“收集中”里，一并改成当场关掉。回传结果也不再整条写“1 个值校验失败”，改成写清收到几个新值、哪些字段没通过，例如“收到 1 个新值，device 未通过校验”。手机通知直接显示这段文字，`ferry.js` 不用改。有新值时结果记为 `accepted`，这样“变化时通知”也会提示；没通过的字段写在结果文字和 `rejected` 里，审计详情也写上。
  - 来源编辑器的样例请求连同真实请求头存在 localStorage 里，而且一直不清。改存 sessionStorage，并加“清除样例”按钮。

### 6. 新增功能

1. **来源编辑器**：
   - 粘贴 cURL 命令或原始 HTTP 请求，直接生成样例请求。
   - 在样例里点选请求头、Cookie、查询参数、JSON 路径，直接添加字段，取值位置自动填好。

## 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 改名涉及的地方多，有遗漏 | 新旧说法混在一起 | 按旧词核对清单 grep；代码注释不在范围内，免得改动扩散 |
| 旧订阅没有下载记录 | 状态判断不准 | 拉过规则的按已连通算；没有下载时的 MITM 哈希就不判断待更新 |
| 数据多了以后统计接口变慢 | 总览加载慢 | 只做计数查询，限定在 7 天内；需要时补索引 |
| 侧栏角标定时刷新 | 请求变多 | 60 秒一次，切换页面时顺带刷新；接口只做计数 |
| 六个阶段改的是同一批页面 | PR 之间冲突 | 按顺序合并，后一个 PR 基于最新的 main |
| 已有测试库的数据 | 升级后出问题 | 迁移只加列；每个阶段合并后，在测试实例上验一遍 |
