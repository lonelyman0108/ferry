## 背景与目标

目前手机脚本拉规则（`GET /api/v1/rules`）和回传（`POST /api/v1/sync`）都是明文 JSON，订阅 token 放在请求头 `X-Ferry-Subscription` 里。链路是否加密完全取决于访问地址是不是 https。访问地址是 http 时（局域网直连、懒得配证书、临时测试），同一网络里的人能直接读到登录态和订阅 token，拿到 token 后还能冒充手机写入假值。

**目标**：即使访问地址是 http，手机和 Ferry 之间的数据通道也做到：

1. **读不到**：登录态、字段名、来源名、规则内容、服务端的回复都是密文；
2. **改不了**：任何改动都会被识别并丢弃；
3. **不能重放**：截获的旧请求再发一次会被拒绝（否则旧 token 能把当前值覆盖回去）；
4. **不能冒充**：没有密钥的一方既伪造不出请求，也伪造不出服务端的回复；
5. **不能降级**：攻击者不能诱导已用过加密的手机退回明文发送。

**不做**：替代 HTTPS（能上 HTTPS 仍然优先）、前向保密、隐藏“手机在和某台服务器通信”这件事本身。

## 威胁模型

| 攻击者能力 | 现状（http） | 本计划之后 |
|---|---|---|
| 被动窃听手机和服务器之间的数据通道 | 全部明文可见 | 只能看到密文、订阅的公开编号、包长度和时间 |
| 主动篡改、重放、伪造数据通道里的请求或回复 | 都能做到 | 都会被识别并拒绝（AEAD 加时间窗加 nonce 去重，回复绑定请求） |
| 诱导手机退回明文 | — | 手机一旦走过加密，就不再发明文；服务端对已加密的订阅拒收明文 |
| **篡改代码分发**：替换 http 下载的订阅文件或 `ferry.js` | 能做到 | **加密防不住**，见下文 |
| 拿到订阅文件 / 订阅链接 | 等于拿到 token | 拿不到密钥：密钥只在客户端本地的模块参数里，不在订阅文件里 |
| 控制手机或服务器本身 | — | 不在防护范围内 |

**代码分发是加密解决不了的问题。** 客户端会执行它下载到的任何脚本。如果订阅文件或 `ferry.js` 走 http 下载，主动攻击者可以把脚本换成恶意版本：恶意脚本运行在能看到 App 原始请求的位置，加密也就失去了意义。所以本计划把要求缩小到“**安装和更新订阅、下载脚本的那一刻，通道是可信的**”（局域网、https 或固定版本的 https 静态地址，见设计 §6），此后数据通道可以放心走不可信的 http。

**管理界面也必须走可信通道**（本机、局域网或 https）。密钥从管理界面复制出来；何况后台会话本身就能读出所有值，管理界面不安全时，传输加密没有意义。

## 详细设计

### 1. 密钥

- 每个订阅一把随机密钥 `K`（32 字节），另配一个**公开编号** `kid`（12 位随机 base32，唯一索引），用来让服务端找到密钥；`kid` 不是秘密。
- 存储：`subscriptions` 新增 `transport_mode`、`transport_kid`、`transport_key_sealed`（用主密钥加密，AAD 为 `subscriptions/{id}/transport_key`）、`transport_verified_at`（最近一次更换密钥后第一次成功解密的时间）、`transport_last_at`。
- 两个方向用不同的子密钥，防止把服务端的回复当成请求反射回去：
  - `K_up   = SHA-512("ferry/v1/up"   ‖ K)[0:32]`
  - `K_down = SHA-512("ferry/v1/down" ‖ K)[0:32]`
  - 用 SHA-512 是因为 tweetnacl 自带 SHA-512，JS 端不需要额外实现 HMAC。
- **更换密钥**：生成新的 `K`，`kid` 不变，`transport_verified_at` 清空。旧密钥立即失效；手机收到 401 后提示“密钥已失效，请在模块参数里填入新密钥”。
- 订阅 token 仍然保留，只用来下载订阅文件。`sealed` 订阅的数据通道不再接受 token。

### 2. 报文格式

请求：

```
POST {base}/api/v1/sealed
X-Ferry-Kid: <kid>
Content-Type: text/plain

f1.<base64url( nonce[24] ‖ secretbox(明文, nonce, K_up) )>
```

明文：

```json
{ "v": 1, "op": "sync", "ts": 1792000000123,
  "etag": "…",                       // 只在 op=rules 时带
  "body": { "source": "…", "matcher": "…", "fields": { … }, "seen_at": 1792000000 } }
```

- 用 base64 文本而不是二进制正文，是因为各客户端 `$httpClient` 对二进制 body 的处理不一致。
- `f1.` 是格式版本，以后换算法时换前缀。
- nonce 本身就是这条消息的唯一编号，用于去重。

回复：解密成功的请求，HTTP 状态码一律是 200，真实结果放在密文里：

```
f1.<base64url( nonce'[24] ‖ secretbox({ "v":1, "re":"<请求 nonce 的 base64url>", "status":200, "etag":"…", "body":{…} }, nonce', K_down) )>
```

- `re` 把回复绑定到具体的请求上：脚本核对 `re` 等于自己刚发的 nonce，攻击者就无法拿一条旧的“已接受”回复来糊弄手机。
- 规则没变时，返回 `status: 304`，也放在密文里。不再用明文的 `If-None-Match` / 304，否则攻击者可以伪造 304，让手机一直用旧规则。
- **解密失败**（`kid` 不存在、密文被篡改、密钥不对）：返回明文 `401`，正文固定，不区分原因。
- 时间超窗或 nonce 重复：这时请求已经解密成功，可以返回加密的 `status: 409`，附上服务端时间，方便脚本提示“手机时间偏差过大”。
- 可选：把明文补齐到 256 字节的整数倍，减少按包长猜测内容的余地（阶段 2 的可选项）。

### 3. 服务端处理流程

```
limitByIP → 读 X-Ferry-Kid → 找订阅（必须是 sealed）→ 用主密钥解出 K → 派生 K_up / K_down
  → secretbox.Open（失败：401）→ 解析明文 → 检查 ts 在 ±5 分钟内 → nonce 写入去重表（重复：409）
  → 按 op 分发到现有逻辑（rules / sync）→ 结果封装成回复 → 用 K_down 加密
```

- 把 `handleRules`、`handleSync` 拆出与 HTTP 无关的内层函数，返回 `(status, body)`。明文入口和加密入口共用这一层，取值、校验、入库的逻辑都不变。
- **nonce 去重表** `transport_nonces(kid, nonce_hash, expires_at)`，在 `(kid, nonce_hash)` 上建唯一索引，插入冲突就是重放。后台 worker 定期删除过期行。不放在内存里，是为了服务重启后仍然有效。
- **防降级**：`sealed` 订阅调用 `/api/v1/rules`、`/api/v1/sync` 时，按“令牌无效”处理，返回 401。
- **审计**：解密失败按 `kid` 计数并限频记录（`transport.decrypt_failed`），用来发现有人在试探；成功的回传沿用现有的审计。正文大小沿用 1 MiB 上限。

### 4. 密钥怎么到手机上：模块参数

- 生成订阅时有一个“传输加密”开关。打开后，服务端生成 `K` 和 `kid`，订阅文件里只声明一个**空的** `key` 参数，在脚本参数里引用它。以 Surge 为例：

  ```
  #!arguments=key:
  #!arguments-desc=key：Ferry 传输密钥，在 Ferry 后台的订阅详情里复制
  …
  argument="base=http://…&kid=<kid>&mode=sealed&key={{{key}}}"
  ```

  Loon 用 `[Argument]` 声明输入项；Stash、Egern 以阶段 0 的结论为准。

- 用户在客户端里添加模块后，把后台复制的密钥粘贴进模块参数。复制时记一条审计。用 Apple 的通用剪贴板或隔空投送传到手机上即可，不需要手打。
- **密钥由服务端生成，不让用户自己设**：抓到的密文可以离线反复试密钥，用户自定的口令熵太低，会被穷举；要防穷举就得在手机上每次跑 scrypt 这类慢哈希，代价太高。服务端生成 32 字节随机数，用 base64url 编码成 43 个字符、不带填充。这些字符都不会和 query 的分隔符冲突，可以直接放进参数。
- 填完后，脚本第一次运行时会发一次加密的 `op: "ping"`，通知“已连上 Ferry，传输已加密”或“密钥不对”。
- 客户端没有模块参数（QX），或模块参数在更新模块后不保留时，这个客户端不提供加密选项。不能把密钥写进订阅文件：那样拿到订阅文件就等于拿到了密钥。

### 5. 手机端脚本

- **选择通道**：
  - 参数里有 `key`：只走加密通道。同时在 `$persistentStore` 里记下 `ferry.sealed.<kid>` 和 `ferry.sealed.any`。
  - 参数里没有 `key`，但本地记录过这个 kid 或任何 kid 走过加密：不联网，放行原请求，每小时最多提示一次“请在模块参数里填写密钥”。这样即使订阅文件被改、`key` 参数被去掉，也不会退回明文。
  - 参数是 `mode=plain`，且本地从没走过加密：走现有的明文流程。
- **订阅参数**：`sealed` 订阅的参数是 `base`、`fallback`、`kid`、`mode`、`key`（后者由客户端替换成用户填的值），不再带 token。
- **只认本地记录、不认参数**：降级保护看的是本地记录，不看订阅参数怎么写。用户确实要退回明文时，在后台把订阅切回 `plain` 并重新安装模块；脚本看到服务端加密回复的 `mode: plain` 后才清掉本地记录。
- **加密库**：tweetnacl 的子集（secretbox、SHA-512），加上自写的 base64url 和 UTF-8 编解码（有的引擎没有 `atob` 和 `TextEncoder`），全部保持 ES2015。
- **随机数**：
  - 有 `crypto.getRandomValues` 时用它。
  - 没有时拼一个：6 字节毫秒时间戳 + 4 字节持久化计数器 + 14 字节 `Math.random`。XSalsa20 对 nonce 的要求是不重复，不要求不可预测，这样拼出来足够。
- **核对回复**：解密失败或 `re` 不符时，按回传失败处理，通知写“回复校验失败”，不更新本地的去重哈希。
- **401**：通知“密钥不对或已更换，请在模块参数里填入后台显示的密钥”，每小时最多一次。

### 6. 代码与订阅的分发

- **脚本地址可配置**：订阅或访问地址上新增“脚本地址”选项，可以填任何 https 静态地址（自己的 https 站点、GitHub Release 附件、jsDelivr 固定到版本号的地址）。`ferry.js` 本来就是通用的、不含密钥，放在公开地址上没有问题。
- 主访问地址是 http 且脚本地址没改时，管理界面提示：“数据已加密，但脚本经 http 下载，可能被替换”。
- **订阅文件**：不含密钥，只有空的参数声明。界面提示“在可信网络（家里局域网或 https）下安装和更新模块”。订阅文件被替换的风险写进「风险」，作为残留风险。

### 7. 兼容与迁移

- 已有订阅保持 `plain`，在界面上一键切到 `sealed`。切换后要刷新模块（订阅文件变了）并填写密钥；填好之前回传会暂停。
- 明文接口继续保留给 `plain` 订阅使用，本计划不删除。
- `ferry.js` 同时支持两种模式；旧版脚本遇到 `sealed` 订阅时，因为参数里没有 token，会直接放行原请求，不会误发明文。
- QX 订阅只能是 `plain`；界面在 QX 上隐藏加密开关，并提示“QX 不支持模块参数，建议使用 https 访问地址”。

## 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 订阅文件或脚本经 http 下载时被替换 | 恶意脚本直接读到 App 原始请求，加密失效 | 脚本地址可以配成 https 静态地址；界面提示在可信网络下安装和更新；写进 README 的安全说明 |
| 客户端更新模块时清掉已填的参数 | 每次更新后回传暂停，要重新填 | 阶段 0 验证；脚本通知提示重新填写；不保留的客户端改用扫码配对（初稿方案） |
| QX 没有模块参数 | QX 用户无法加密 | QX 只提供明文，界面提示改用 https 访问地址 |
| 密钥在复制粘贴途中泄露 | 他人能解密和伪造 | 通用剪贴板和隔空投送本身是端到端加密的；后台可随时更换密钥 |
| 脚本环境没有安全随机数 | nonce 只能保证不重复，不能保证不可预测 | XSalsa20 只要求 nonce 不重复；用时间戳加持久化计数器保证 |
| 手机时间不准 | 请求因超窗被拒 | 加密的 409 回复里带服务端时间，提示用户校时；时间窗设为 ±5 分钟 |
| 同一客户端里的其他脚本能读 `$persistentStore` | 密钥可能被其他模块读走 | 这些脚本本来就能读到 App 的原始请求，不额外增加暴露面；在 README 里说明 |
| 没有前向保密 | 密钥泄露后，之前抓到的包都能解开 | 提供“更换密钥”；能上 https 的仍然优先 https |
| 元数据仍然可见 | 能看到 `kid`、服务器地址、包长和通信时间 | 可选的长度补齐；不再继续扩大范围 |
