## 背景

维护者提出三项需求：来源的快速导入改为 JSON；新建一个公开的来源仓库（hub），规定提交规则；新增浏览功能，可添加第三方仓库并勾选其中的来源导入。之后补充第四项：部分网络环境无法直连 GitHub，所有访问 GitHub 的位置都要支持代理设置，提供几种预置选项与自定义。

安全重点在探测请求：`probe` 的地址、请求头、请求体可以引用字段模板（如 `{{.authorization}}`），第三方提供的来源定义可借此把登录态发往任意域名。因此导入链路的每个入口都要做同一套规则检查，违反硬规则的条目必须明确标红、单独确认。

## 决策

| # | 问题 | 决定 |
|---|---|---|
| 1 | 导入格式 | 彻底换成 JSON：来源导入、导出、内置示例都不再使用 YAML（配置文件与 Stash 订阅仍用 yaml 库）。v0.1.0 导出的 `.yaml` 不再兼容 |
| 2 | 文件结构 | 带外壳：`{"$schema", "format": 1, "meta": {version, author, homepage, tags}, "source": {…}}`，导出、导入、hub 共用；`meta` 不进入来源定义。来源图标沿用 `source.icon` |
| 3 | 导入入口 | 四种都要：粘贴或选择文件；填写链接（服务端拉取）；一次多个（数组或多个文件）；一键导入链接 `<访问地址>/sources/import?url=…`（只打开预览，确认后才写入） |
| 4 | key 冲突 | 在预览里二选一：覆盖更新（保留身份、历史版本、推送规则）或改用新 key 另存 |
| 5 | hub 托管 | GitHub 公开新仓库 `lonelyman0108/ferry-hub` |
| 6 | hub 目录 | 每个来源一个目录：`sources/<key>/{source.json, README.md, cases.json}`；根目录 `index.json` 由工具生成 |
| 7 | 硬规则（CI 拦截，导入时标红） | 探测地址的域名必须在匹配规则的域名内；匹配规则的域名不得为过宽的通配；必须附带脱敏样例（仅 hub）。关闭手机通知、开启调试只警告不拦截 |
| 8 | 版本号 | `meta.version` 为整数，每次修改递增；CI 检查改动的来源版本号变大 |
| 9 | 浏览的含义 | 浏览仓库时勾选其中的来源导入；不做「把本地来源关联到仓库」 |
| 10 | 官方仓库 | 默认添加、可停用；九号出行示例迁入 hub，移除二进制内置示例与「从示例导入」 |
| 11 | 更新 | 记录来源出自哪个仓库、哪个版本；有新版时显示「有更新」，查看差异（本地改过时提示将被覆盖）后确认应用 |
| 12 | 第三方安全 | 违反硬规则的条目在所有导入方式中标红，勾选「我已了解风险」后才能导入；手动新建的来源不受影响 |
| 13 | GitHub 网络模式 | 直连；镜像前缀（预置 ghfast.top、gh-proxy.com、ghproxy.net，可自定义）；网络代理（HTTP 或 SOCKS5） |
| 14 | 代理作用范围 | 只作用于 GitHub 域名（github.com、raw.githubusercontent.com、objects.githubusercontent.com、codeload.github.com 等），其他地址照常直连 |
| 15 | 检查更新 | 改为读取 `github.com/<仓库>/releases/latest` 的跳转地址，不再调用 api.github.com（镜像前缀通常不代理 API） |
| 16 | 非 GitHub 仓库 | 照常导入，预览中注明网络设置不适用于该地址 |

## 阶段 1 · 来源 JSON 格式与导入

- [x] 外壳类型与解析：`format` 只接受 1；未知顶层字段报错；`meta.version` 为正整数；一个文件可以是单个外壳或外壳数组；单次导入数量与大小有上限
- [x] JSON Schema：`schema/source.v1.json` 放在本仓库，`$schema` 指向它在 GitHub 上的地址；测试保证 Schema 与 `source.Doc` 字段一致
- [x] 规则检查独立成包，供导入预览、`ferry source check`、hub CI 共用：探测域名在匹配域名内（含模板展开前后的地址）、匹配域名不过宽、通知关闭与调试开启给出警告
- [x] 子命令 `ferry source check <文件…>`：校验外壳、来源定义与规则，hub 模式下另查样例；输出中文结果，违规时退出码非零
- [x] 导入接口改为两步：预览（`text` 或 `url`）返回每个条目的解析结果、key 冲突、本地是否改过、规则违规与警告；应用（逐条带上「覆盖更新」或「新 key」以及风险确认）。应用逐条写入，失败的条目单独报错
- [x] 链接导入：服务端拉取，只允许 http、https，限制大小与超时，不跟随跳到非 http(s) 的地址；GitHub 地址走阶段 2 的网络设置（阶段 2 完成前直连）
- [x] 覆盖更新沿用编辑器保存的语义：保留身份、历史版本、推送规则；字段删减的处理与编辑器一致；写审计记录
- [x] 导出改为 JSON 外壳（`ferry-<key>.json`），`meta.version` 取已记录的版本，没有时为 1
- [x] 界面：「导入」对话框替换「导入 YAML」，支持粘贴、选择多个文件、填写链接；预览列表逐条显示头像、名称、冲突选择、规则违规（标红，单独勾选「我已了解风险」）与警告；`/sources/import?url=…` 路由打开同一预览，未登录时登录后回到该地址
- [x] 移除来源的 YAML 读写；内置的九号出行示例改为 JSON 外壳（阶段 4 迁入 hub 后删除）；后端与前端测试、文档同步

## 阶段 2 · GitHub 网络设置

- [x] 出站请求统一封装：一个只服务 GitHub 域名的 HTTP 客户端，按设置改写为镜像前缀地址或经网络代理发出；其他域名照常直连。现有的检查更新、阶段 1 的链接导入、阶段 4 的仓库拉取都改用它
- [x] 设置项存入 settings 表：模式、镜像前缀（预置或自定义）、代理地址；代理地址里的用户名密码用主密钥加密保存，接口只返回脱敏形式
- [x] 输入校验：自定义前缀须为 https 地址；代理须为 `http://`、`https://`、`socks5://`、`socks5h://`
- [x] 检查更新改读 `github.com/<仓库>/releases/latest` 的跳转，从跳转地址取版本号，不再依赖 API；补测试
- [x] 界面：「设置」新增「网络」子页，三种模式的单选、预置镜像列表与自定义输入、「测试连接」（拉取一个小文件，显示结果与耗时）
- [x] 实测三个预置镜像对 raw 文件、releases/latest 跳转、发布附件的支持情况，结果记在本计划；不可用的从预置中移除或注明：
  - `https://ghfast.top`：raw 文件（200）、`releases/latest` 跳转（302，`Location: /https://github.com/<owner>/<repo>/releases/tag/<tag>`）、发布附件（200）全部支持
  - `https://ghproxy.net`：raw 文件（200）、`releases/latest` 跳转（302，`Location: /https://github.com/<owner>/<repo>/releases/tag/<tag>`）、发布附件（200）全部支持
  - `https://gh-proxy.com`：raw 文件（200）、发布附件（200）支持；`releases/latest` 返回 200 引导页 HTML，不转发跳转（已在预置说明中注明）
- [x] 非 GitHub 地址的仓库与链接，在预览与仓库详情中注明网络设置不适用
