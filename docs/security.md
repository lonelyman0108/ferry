# 安全模型

> Ferry 经手的是登录态——它们本身就是钥匙。所以这里的原则只有一条：**原文能不出现，就不出现；必须出现，就留下痕迹。**

关于漏洞的私下报告方式，见仓库根目录的 [SECURITY.md](../SECURITY.md)。

## 设计要点

- **主密钥**：初始化时生成，用来加密敏感字段的值、订阅令牌原文、目的地和通知渠道的整份配置。丢失后这些数据无法解密，要和数据库一起备份。
- **令牌分三种**：
  - 管理员会话放在 Cookie 里，30 天有效；用 Cookie 的写请求必须是 JSON，跨站页面发不出这种请求。
  - API 令牌 `fy_` 只读，不返回敏感原值。
  - 订阅令牌 `fs_` 只能拉订阅文件、规则和回传（加密订阅只用它下载订阅文件），数据库里存哈希和一份加密原文，可以随时更换。
- **初始化向导**：未初始化时，每次启动在日志里打印一次性令牌，向导必须凭它访问；初始化完成后向导接口不再可用。
- **只写不读**：目的地和通知渠道的密钥保存后不回显，编辑时留空表示不改。
- **查看原值要留痕**：界面上默认只显示敏感值的掩码，点“显示”才向后端要原文，并写一条审计记录。
- **传输加密**（[ADR 0004](adr/0004-transport-encryption.md)）：订阅可以开启加密传输。开启后，手机和平台之间的整个报文用每个订阅一把的传输密钥加密（NaCl secretbox），访问地址是 http 时也读不到、改不了；带时间窗和 nonce 去重，不能重放；回复绑定请求，不能冒充平台。
  - 密钥由平台生成，用户从订阅详情里复制，填进客户端的模块参数；订阅文件里只有密钥编号，没有密钥，也没有令牌。
  - 开了加密的订阅不再接受明文接口；手机走过加密后也不会退回明文。
  - 防不住的：订阅文件和脚本本身走 http 下载时可能被替换，请在可信网络（家里局域网或 https）下安装和更新模块；管理界面也应在可信网络里打开。Quantumult X 没有模块参数，只能明文，建议给它用 https 访问地址。
- **限流**：登录失败 15 分钟内超过 5 次即锁定；手机端接口按 IP 限流，每分钟 120 次。不信任 `X-Forwarded-For`，避免伪造转发头绕过限流。

## 能防的，与不能防的

| 威胁 | 应对 | 结论 |
|---|---|---|
| 数据库文件泄露 | 敏感值、订阅令牌原文、目的地与渠道配置都由主密钥加密，密文绑定所在行（AAD） | 只拿到库、没拿到主密钥，读不出原文 |
| 局域网里有人旁听或篡改回传 | 开启传输加密后整个报文加密、带时间窗与 nonce 去重，回复绑定请求 | http 地址下也读不到、改不了、重放不了 |
| 跨站页面替你发写请求 | 用 Cookie 的写请求必须是 JSON，跨站表单发不出 | 防得住 |
| 暴力尝试登录 | 15 分钟内失败超过 5 次即锁定，不信任 `X-Forwarded-For` | 防得住 |
| 订阅令牌泄露 | 令牌只能拉订阅、规则与回传，随时可以更换 | 影响限于这一个订阅，换掉即可 |
| 安装或更新模块时脚本被替换 | — | **防不住**：请在可信网络（家里局域网或 https）下安装和更新 |
| 主密钥与数据库一起泄露 | — | **防不住**：两者分开保管，备份同样分开 |

## 事件不带值

事件、通知、审计记录、回传响应里只有来源、身份和字段名，从不包含登录态原文。通知渠道（包括用作通知的 Webhook）收到的是“哪个来源的哪个字段更新了”，而不是值本身；只有推送到目的地时，值才会离开 Ferry。
