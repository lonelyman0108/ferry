# 上手教程

> 从一台空白的 Ferry 开始，走完一条完整的链路：**手机上的 App → Ferry → 青龙里的环境变量。** 全程十分钟左右。

下文以内置示例「九号出行」为例；换成别的 App，只是来源的配置不同。

## 0. 启动

最快的方式是 Docker：

```bash
docker run -d --name ferry -p 8080:8080 -v ferry-data:/data ghcr.io/lonelyman0108/ferry:latest
docker logs ferry
```

日志里有一行 `setup_token=…`，这是初始化令牌，每次启动都会变。compose、PostgreSQL 与二进制的用法见 [部署与配置](deployment.md)。

## 1. 初始化

打开管理界面，向导依次要你填：

| 步骤 | 要做的事 |
|---|---|
| 初始化令牌 | 粘贴日志里的那一串 |
| 数据库 | SQLite 保持默认的 `ferry.db` 即可（用镜像时落在 `/data` 里）；PostgreSQL、MySQL 填连接串，可以先测试连接。环境变量已经给出时会自动回填 |
| 管理员 | 用户名和密码 |
| 访问地址 | 手机访问 Ferry 用的地址，比如 `http://192.168.1.10:8080`；也可以以后在 **设置 → 访问地址** 里加 |
| 确认 | 核对一遍再提交 |
| 主密钥 | 提交后生成并只显示这一次。**当场备份**，丢了就再也解不开加密的数据 |

数据库和主密钥已经由环境变量给出时，向导只问管理员与访问地址。

## 2. 新建来源

来源描述的是：**哪个 App 的哪些请求里，取哪些值，拼成什么变量。**

进入 **来源 → 从示例导入**，选「九号出行」。打开它，在 **编辑读取规则** 里能看到四个部分：

- **请求匹配**：域名、路径正则、请求方法。
- **字段**：从请求头、Cookie、URL 参数、JSON 正文或表单里取值；类型选 JWT 时，过期时间会被自动读出。
- **输出变量**：用模板把字段拼成推给目的地的变量，例如 `NINEBOT_AUTHORIZATION = {{.authorization}}`。
- **有效性检测**（可选）：新值生效前，用它请求一次目标服务，确认登录态真的能用。

编辑器右侧可以贴一段样例请求，每个部分的匹配与取值结果都会当场显示，规则写对了没有，不用上手机就知道。

## 3. 安装订阅

订阅是给某一台设备、某一个代理客户端生成的插件。进入 **订阅 → 新建订阅**，选客户端和访问地址，再选它覆盖哪些来源（默认全部）。

保存后打开 **安装**：

1. 在手机上点 **在这台手机上打开**，或扫码，把订阅装进客户端（Surge、Shadowrocket、Egern 里叫模块，Loon 里叫插件，Quantumult X 里叫重写，Stash 里叫覆写）。
2. 在客户端里开启 MITM，生成并安装 CA 证书，再到 iOS 的 **设置 → 通用 → 关于本机 → 证书信任设置** 里信任它。订阅会自动带上需要的域名。

访问地址是 http 时，建议在订阅里开启**传输加密**：安装引导会多出一步“填写传输密钥”，把密钥填进客户端的模块参数即可，原理见 [安全模型](security.md)。

## 4. 让登录态回来

在手机上正常打开九号出行，进到签到页。脚本在请求经过时取出字段、回传给 Ferry，手机上会弹出一条通知。

回到管理界面的 **总览**：设备到来源的连线变成实线，来源卡片上出现身份数与最早过期时间。点进来源，能看到每个身份的当前值（敏感值只显示开头和结尾）。

如果来源设了人工审核，新值会出现在总览左上角的 **待处理** 里，点 **通过** 即生效。

## 5. 推到青龙

先在青龙里新建一个应用（**系统设置 → 应用设置**），只勾选“环境变量”权限，记下 Client ID 与 Client Secret。

回到 Ferry：

1. **推送 → 目的地 → 新建目的地**，类型选青龙，填青龙地址与上面两项，点 **测试连接**。
2. **推送 → 推送规则 → 新建推送规则**，选来源与目的地：
   - **每个身份一条**：每个账号写一条变量，备注 `ferry:<来源>:<身份>`；
   - **合并为一条**：多个账号用 `&` 连在一条变量里，备注 `ferry:<来源>`。
   需要的话可以给变量改名。

新值生效后会自动推送。Ferry 只管理备注以 `ferry:` 开头的变量，你手工维护的变量它不会碰。

## 6. 出事时提醒你

**推送 → 通知 → 新建通知渠道**，选 Bark、Telegram 或 Webhook，发一条测试；再建一条 **通知规则**，比如“推送失败、登录态即将过期 → Bark”。

## 之后的日常

- **总览** 一眼看通断，待处理里的事就地处理。
- 点任一节点进入 **聚焦**，只看与它相关的链路与详情；按 Esc 回到全图。
- **记录** 里能按来源查看每一次回传、审核、推送与通知。
- 按 ⌘K（Windows 上 Ctrl+K）随时跳转或执行命令。
